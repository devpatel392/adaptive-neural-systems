# Research plan

## Central hypothesis

> A retrieval-and-reasoning system whose strategy selection is **learned from measured retrieval outcomes** will retrieve more relevant evidence per query than any fixed strategy (lexical, dense, hybrid or graph), and the improvement will exceed seed-to-seed variance on a held-out test set.

Supporting hypotheses, each tested in its own phase:

- **H1 (foundations).** A from-scratch NumPy MLP reaches the same test accuracy as an equivalent PyTorch model given the same initialisation and data. This would confirm our understanding of backpropagation.
- **H2 (retrieval).** Hybrid lexical+dense retrieval beats each component alone on recall@k for our corpora.
- **H3 (graphs).** Graph-based retrieval improves recall on multi-hop questions specifically, measured on questions whose hop count is known from the dataset, not guessed by us.
- **H4 (adaptation).** LoRA fine-tuning of a small model improves answer quality on a held-out domain set compared with the same model using retrieval alone.
- **H5 (continual learning).** Updating weights from verified feedback improves new-task performance with bounded forgetting on earlier tasks.

These are hypotheses. A negative result is a valid, reportable outcome.

## Baseline methods

| Question | Baselines |
| --- | --- |
| Classification (Phase 1) | Majority class; logistic regression |
| Retrieval quality | BM25; dense retrieval; hybrid fusion |
| Router | Best single strategy; always-hybrid; simple heuristic; random choice; oracle upper bound |
| Generation | Model without retrieval; model with BM25 retrieval |
| Fine-tuning | Base model + retrieval, no fine-tuning |
| Continual learning | Retraining from scratch on all data (upper bound); no updates (lower bound) |

## Evaluation metrics

- **Classification:** accuracy, macro-F1, cross-entropy loss on held-out data.
- **Retrieval:** recall@k, precision@k, MRR (mean reciprocal rank), nDCG@k.
- **Router:** downstream recall@k of the chosen strategy; regret relative to the oracle; routing accuracy against measured-best labels.
- **Generation:** exact match / token F1 where references exist; faithfulness, i.e. whether claims are supported by the retrieved evidence.
- **Continual learning:** average accuracy over all tasks seen so far; backward transfer (forgetting).
- **Cost:** wall-clock training time, peak RAM and inference latency on the reference laptop.

Every reported number is the **mean ± standard deviation over at least 3 seeds** unless stated otherwise.

## Experimental protocol

1. Fixed train / validation / test splits, created once with a recorded seed and saved as index files.
2. Hyperparameters are tuned on validation only. The test set is evaluated once per final configuration.
3. Every run records its config, seed(s), git commit hash, package versions and hardware.
4. Results are produced by code in `experiments/`. Numbers are never typed into documents by hand.
5. Labels are sourced from datasets with documented provenance, or computed by a documented procedure. They are never fabricated or assigned by intuition.

## Milestone completion criteria

| Phase | Done when |
| --- | --- |
| 0 | Package imports; tests and lint pass; documentation reviewed |
| 1 | Analytical gradients match numerical gradients (relative error < 1e-6); MLP beats both baselines on the test set across ≥ 3 seeds; results generated by a script |
| 2 | Transformer training loss decreases reliably; validation perplexity beats a unigram/bigram baseline |
| 3 | Evaluation harness computes all retrieval metrics with unit tests; baselines reported |
| 4 | KG built with provenance; GraphRAG evaluated against hybrid |
| 5 | Router evaluated against all baselines and the oracle on held-out queries |
| 6 | Feasibility documented; fine-tuned model compared with retrieval-only baseline |
| 7 | Forgetting measured and reported alongside new-task gains |
